# PDF Requirements Extractor

## 🚀 Возможности

- **Автоматическое извлечение требований** из PDF-документов (любое количество страниц)
- **Интеграция с DeepSeek API** для интеллектуального анализа текста
- **Веб-интерфейс** с drag&drop загрузкой файлов
- **Real-time прогресс-бар** с детальными логами обработки
- **WebSocket** для мгновенного отображения прогресса каждой страницы
- **Отслеживание использования и стоимости** - автоматический подсчет токенов и затрат
- **Структурирование данных** по разделам и типам требований
- **Типизация требований**: технические, функциональные, организационные и др.
- **Приоритизация**: обязательные, желательные, опциональные
- **Экспорт в JSON и Word** с подробной структурой и отчетами
- **Детальные отчеты** о затратах на API в Word документе
- **Логирование** всех операций с real-time отображением
- **Обработка ошибок** с повторными попытками

## 📋 Требования

- Python 3.11+
- DeepSeek API key
- Зависимости из `requirements.txt`

## 🎯 Использование

### 🌐 Веб-интерфейс (Рекомендуется)

Самый простой способ использования системы - через веб-интерфейс:

1. **Запустите API сервер:**
```bash
python api_server.py
```

2. **Запустите фронтенд (в новом терминале):**
```bash
python -m http.server 8080
```

3. **Откройте браузер:**
```
http://localhost:8080/frontend/
```

4. **Используйте интерфейс:**
   - Перетащите или выберите PDF файл
   - Нажмите "Начать обработку"
   - Наблюдайте за прогрессом в real-time:
     - 📄 Извлечение страниц: 1/225, 5/225, 10/225...
     - 📚 Анализ структуры документа
     - 🤖 Извлечение требований с DeepSeek AI
     - ✅ Результаты готовы!
   - Скачайте результаты:
     - Word документ (Реестр + Отчет)
     - JSON реестр требований
     - Текстовый отчет о затратах

**Примечание:** WebSocket подключается автоматически при загрузке страницы. Все логи и прогресс отображаются в real-time.

#### 🔍 Отладка веб-интерфейса

Если прогресс не отображается:

1. Откройте консоль браузера (F12)
2. Проверьте наличие сообщения: `[WS] WebSocket connected`
3. При обработке должны появляться: `[PROGRESS] 21% - 📄 Extracting pages: 1/225`
4. В терминале API должно быть: `[PROGRESS] Sending: 21% - ...`

Для детального тестирования WebSocket используйте:
```
http://localhost:8080/test_websocket.html
```

Полное руководство по отладке: `PROGRESS_DEBUG_GUIDE.md`

### Базовое использование через Python API

```python
from pathlib import Path
from src.extractor import create_extractor

# Создать экстрактор
extractor = create_extractor(
    pdf_path=Path("data/input/specification.pdf"),
    output_dir=Path("data/output"),
    log_level="INFO"
)

# Запустить извлечение с ручным TOC
manual_toc = [
    {
        "level": 1,
        "number": "1",
        "title": "Введение",
        "page_start": 1,
        "children": []
    },
    # ... другие разделы
]

registry_path = extractor.run_full_extraction(manual_toc=manual_toc)
print(f"Реестр сохранен в: {registry_path}")
```

## 🛠️ Архитектура

### Основные компоненты

1. **DeepSeekClient** - клиент для API DeepSeek
   - Парсинг оглавления
   - Извлечение требований
   - Обработка ошибок и повторные попытки

2. **PDFProcessor** - обработка PDF документов
   - Извлечение текста по страницам
   - Сохранение изображений
   - Получение текста по разделам

3. **RequirementsExtractor** - основной оркестратор
   - Координация всего процесса
   - Управление состоянием
   - Сохранение результатов

4. **Models** - модели данных
   - Requirement - отдельное требование
   - Section - раздел документа
   - TableOfContentsEntry - запись в оглавлении
   - RequirementsRegistry - полный реестр

### Типы требований

- `TECHNICAL` - Техническое
- `ORGANIZATIONAL` - Организационное
- `DOCUMENTATION` - Документационное
- `FUNCTIONAL` - Функциональное
- `NON_FUNCTIONAL` - Нефункциональное
- `OTHER` - Прочее

### Приоритеты

- `MANDATORY` - Обязательно
- `RECOMMENDED` - Желательно
- `OPTIONAL` - Опционально

## 📝 Логирование

Логи сохраняются в:
- `logs/extraction.log` - основные логи
- `logs/test_extraction.log` - логи тестового запуска

Уровни логирования: DEBUG, INFO, WARNING, ERROR

## ⚠️ Обработка ошибок

Система включает:
- Автоматические повторные попытки при сбоях API (3 попытки)
- Экспоненциальная задержка при rate limiting
- Валидация конфигурации
- Graceful degradation (продолжение работы при ошибках отдельных секций)

## 🔐 Безопасность

- API ключи хранятся в `.env` (не в git)
- Логи не содержат чувствительной информации
- Валидация входных данных
- Безопасная работа с файловой системой
